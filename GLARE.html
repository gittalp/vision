Browser glare analysis

VisionSim HDR Web 0.9

Actual evalglare 3.06 is included and runs in the browser. No Python, local Radiance executable, or image upload is used. The supplied loader and WebAssembly binary are unchanged; their checksums and actual version banner are recorded. Native-Windows equivalence is not claimed.

Input requirement: use scene-linear HDR/EXR or a calibrated bracket reconstruction. The glare preparation rejects ordinary photographs and the phone-HDR import route even after single-patch anchoring; that anchor cannot undo local tone mapping or validate the captured dynamic range.

Separate, optional workflow

Skip glare leaves the rest of the workspace available. The glare panel receives a separate calibrated luminance copy. It does not apply the current named-region restriction, annotation colors, viewing mask, false-color mapping, display exposure, or low-vision filtering. Its reset clears only its own prepared image and results. Geometry, source/crop/mask or calibration changes invalidate its preparation; region names and tints do not.

Geometry and projection conversion

The whole-view route requires a confirmed fisheye geometry, an applied image circle, valid captured data across the forward hemisphere, and an absolute luminance convention. It generates a separate 180-degree angular/equidistant image with VIEW= -vta -vh 180 -vv 180. It does not relabel equisolid pixels as -vth. Vignetting correction and luminance calibration should already describe the original lens/raster before conversion.

For an ideal equisolid image and a centered 180-degree angular output, let q be normalized output radius and u normalized input radius:

theta = (pi/2) q
u = sin(theta/2) / sin(pi/4) = sqrt(2) sin(pi q / 4)
0 <= q <= 1

The actual implementation maps each output viewing ray through the applied source geometry, including shift/lift. This accommodates a confirmed circle that is not exactly centered or fills only part of the source raster. Rays are resampled using 1x1, 2x2 or 4x4 subpixel samples and bilinear source lookup. Subpixel averaging is weighted by solid angle. Luminance itself is not multiplied by a projection Jacobian. Valid edge weights are renormalized; invalid interior samples cause preparation to fail rather than being filled with black.

The source projection remains a user-confirmed property. Lens model names alone do not force the mapping. The ideal mapping is not a per-lens distortion calibration. The user-supplied Sigma 4.5 mm and 8 mm lenses can use the equisolid option when that is the verified mapping.

Luminance and illuminance

L = interpreted source Y * current calibration multiplier
R = G = B = L / 179
Prepared HDR: EXPOSURE=1
Omega_region = sum of pixel solid angles within the valid selected set
E_eye = sum L_i max(0, ray_i dot viewing_normal) Omega_i

The neutral RGB copy avoids changing luminance because of original color-primary conventions. It is only the glare engine input; the source photograph remains in color. RGBE has quantization error, recorded in the preparation tests. The panel's illuminance estimate is calculated before that encoding. It is eye-plane illuminance; it is vertical illuminance only when the viewing normal is horizontal.

A uniform forward hemisphere gives Omega=2 pi sr and E=pi L. The tests verify both, as well as an off-axis bright cap and spatial angular signals. Small bright sources remain sensitive to capture clipping and sampling; repeat at another output resolution before relying on a glare result.

Limited rectilinear views

A rectilinear photograph is not a full hemisphere. The limited-field route retains its actual perspective geometry and requires independently measured eye-plane illuminance. It does not expand the frame into invented surroundings. External illuminance does not recover missing source locations, extents or luminances. Such a result is labeled limited-view, not a complete DGP assessment or a guaranteed lower bound.

Regions and steradians

The existing selection mathematics is unchanged. The explicit Solid angle (sr) column integrates the same valid native source pixels as each region. When B encloses A and automatic subtraction is active, its displayed angle belongs to B minus A. The secondary percentage uses 2 pi sr as a reference, not the camera's pixel count. Absolute calibration is not required for solid angle; confirmed geometry is.

Optional external comparison

This is not used by the browser Run button. The native job ZIP contains the prepared HDR, its checksum, explicit arguments, and a Python runner. It contains no evalglare executable. The runner invokes the user's installed executable without a shell, records its version and checksum, and saves raw output and a check image where available. The website accepts an imported result only when input and argument hashes match the current prepared job. These checks prevent accidental mismatches; they are not a cryptographic authentication of externally supplied results.

Browser engine execution and provenance

The browser worker verifies the bundled JavaScript and WASM checksums, loads the loader's default ES-module factory, and instantiates the verified compiled module through its instantiateWasm hook. This particular build does not consume Module.wasmBinary. FS and callMain stage the prepared HDR and invoke the actual C engine. A fresh instance is used per invocation; arguments are copied because callMain modifies its array. Worker termination cancels engine execution without mutating the active source. The bundled byte sequences have not been patched.

Real-engine tests cover zero, one and two sources, source solid angle, repeated runs, low-light correction, measured illuminance, check images, malformed input and browser result exports. Browser tests use in-memory static-resource delivery because navigation is restricted in the test environment; live-host validation remains separate. The exact engine source commit and compiler configuration were not provided.

Current settings use detailed output, an explicit fixed source threshold, 0.2-radian merging radius by default, configurable peak extraction and explicit low-light correction. They are recorded, not described as optimal settings for every scene. Native -v output may use exit status 1 in the upstream program; the runner checks the version banner rather than interpreting that alone as a failed installation.

Source diagnostics and masks

Results show engine DGP, illuminance, optional secondary metrics and a source table including solid angles. The engine check image is used only for display. A viewing-field overlay does not recalculate glare. Membership currently refers to each source centroid only, not the fraction of its complete footprint. Restricted-field glare recalculation and source-footprint overlap are not implemented in this build.
