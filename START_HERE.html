Deploy the complete folder

Upload hdr-analyzer-v04 beside your existing website. Keep its subfolders and files together. Open its index.html over HTTP(S), not by double-clicking a file. Deploy into a new folder first so the 0.3 installation remains available. No Python, npm, Radiance, or GPU installation is required by visitors.

For your circular fisheye HDR

  1. Open the file. Leave Imported luminance scale on Use available HDR / EXR file scale for your previously calibrated Photosphere HDR. The banner should say Reading cd/m2 - file scale, unverified. Compare a target before entering another calibration.
  2. Start visual crop. Press the button in Section 02 or turn Crop tool on above the image. Choose Circle. Leave crosshair guides and whole-image fit enabled.
  3. Draw around the circle. Drag from one corner of an imaginary square around the lens circle to the opposite corner. Adjust the handles until the boundary matches the useful image. Drag inside to reposition. Arrow keys move by one source pixel; Shift+arrows move by ten.
  4. Apply crop. This trims to the square bounds and excludes the area outside the circle. The numerical luminance of every retained pixel and its scalar calibration are preserved. Alternatively, Exclude outside only masks the circle without changing image dimensions. Nothing changes until you apply.
  5. Continue to FOV / header. Select the actual projection. Use the known image-circle diameter angle to derive raster extents, then review and confirm. Drawing a circle does not establish the lens projection or prove 180-degree coverage.

Use Rectangle for rectangular cropping. Draw new clears a draft. Done / cancel draft or Escape returns to measurement mode without applying it. Undo restores the last applied crop or mask edit, including its saved geometry and calibration state. Numerical coordinate boxes remain under optional disclosures.

Check Photosphere calibration before recalibrating

FOV is not required to inspect pixel or region luminance. Geometry supplies angular information for the visibility model. Crop and mask selection determine which pixels are included; they do not rescale a retained pixel. Whole-image averages can change when the selected region changes.

The earlier application started sources in relative Y, even when a supported absolute file convention was available. That label is visible in the supplied screenshot and is not equivalent to cd/m2. In 0.4 the default HDR/EXR route activates available file scaling with an explicit unverified label. The banner exposes the active multiplier and relevant header fields. Use the relative import choice for deliberately uncalibrated analysis.

For Radiance RGBE/XYZE, accumulated EXPOSURE and channel COLORCORR are already reversed in the reader; the file-convention luminance factor is then applied once. Supported EXR may provide whiteLuminance. Do not multiply the readout by exposure or 179 again. These conventions do not prove that the source camera or photograph was calibrated.

With the crop tool off, hover for a pixel value or drag a rectangle on the measured target. Compare the same target area and the same statistic in Photosphere. A single pixel, an area mean, and a median are different quantities. Only use a new measured-patch anchor when you intend to change the scale.

The real mask-calibration bug is also corrected: applying a circle no longer resets an existing measured-patch multiplier to relative units. If readings still differ with file scale active, retain the original HDR, target region coordinates, Photosphere reading and exported Analysis JSON for comparison. The screenshot-only d10.hdr was not available for an exact numerical check in this update.

First-run acceptance check

Load the synthetic scene. Turn crop mode on, draw a rectangle, move a handle, apply, and undo. Load a known calibrated HDR and verify the unit banner and a target value before and after cropping. Test false color and its legend, then confirm geometry and run a visibility view. No image is sent to a server by the application.

Testing boundary

Numerical and automated Chromium checks cover the new crop interactions, scale preservation, HDR roundtrip, narrow CSS layout, and retained workflows. The runtime blocks HTTP navigation, so browser tests used the actual production bundles in an in-memory page with only the worker URL substituted. Your hosting, Firefox, Safari and physical touch devices still need acceptance testing. Optional HEIC codec limitations are unchanged.
