VISIONSIM HDR WEB · RELEASE 0.3.0

FOV, phone images, color previews,
and luminance false color.

This is a complete, independently deployable update of the web workspace. It does not change desktop VisionSim Beta 6.3, your Resolve export, or the existing educational website. Keep those working versions intact.

Start with a new folder. Upload the complete hdr-analyzer-v03 folder beside the current vision-simulator.html. The core application has no installation step, server processing or image-upload service.

1. Deploy the folder

Extract the ZIP, then upload hdr-analyzer-v03 with its js, licenses, vendor and other included files. Preserve relative paths. Open the hosted folder, for example:

https://visual-accessibility.vt.domains/hdr-analyzer-v03/

This is an intended deployment address, not a claim that the release is already online. Do not double-click index.html: use HTTP(S). The included Windows preview launcher starts a local server when Python is already installed; visitors to the hosted website do not need Python.

For editing source, python build.py rebuilds the two dependency-free production bundles. npm test runs the supplied Node tests without installing npm packages. Python/Node are development tools, not web-host requirements.

2. Luminance false color

Open an image and select Show false color. Set Minimum, Maximum and Linear or Logarithmic. Linear supports zero. Logarithmic requires a positive minimum. Invalid ranges show an error instead of silently changing the numbers.

ControlPurpose
Range presetsAuto P05-P95; full data range; 0-100; 0-1000. Values use the current units, not a hidden assumed calibration.

Uncalibrated files show relative Y. For cd/m², explicitly confirm the file convention or use a measured patch. A file-declared scale is not an independent calibration check. Preview exposure does not move the false-color values.

3. Rectilinear FOV calculator

Section 03 View / header correction now reads available actual focal length, 35-mm equivalent, camera model and focal-plane information. An adequate combination produces a reviewable estimate. Otherwise choose full frame, a typical APS-C preset, Micro Four Thirds, or custom active sensor dimensions.

Use actual focal length with actual active sensor dimensions, or explicitly choose the 35-mm-equivalent mode. Portrait images swap axes correctly. In-app crop history adjusts the estimate; resizing alone preserves FOV. Aspect mismatch requires active dimensions or confirmation of a centered aspect crop.

Press Calculate & use as geometry draft, review the draft, then confirm and apply geometry. The camera-model preset list is deliberately limited, not a universal sensor database. Missing metadata is not guessed from a brand name. The equivalent-focal-length option states its diagonal-equivalence assumption.

Fisheye remains a separate workflow: define/crop the image circle as needed, select the actual projection and known circle angle, then confirm the header. A circular crop alone does not prove 180° FOV. Prepared and header-only HDR exports remain distinct.

4. Phone images and HDR

JPEG imports now handle all eight EXIF orientations. The built-in numerical route recognizes supported Adobe/Android XMP, ISO 21496-1 and Apple XMP headroom gain maps. It decodes base/gain planes separately and reconstructs float32 values above SDR white. The status panel records whether HDR was decoded, an ordinary SDR photo was opened, or an explicitly selected SDR fallback was used.

Unsupported/malformed HDR metadata produces an error by default. SDR base only is an explicit option, not a silent fallback. A rendered phone HDR is still computationally processed; it is not automatically calibrated scene radiance. Use it for appropriately qualified simulation, not unverified absolute photometry.

HEIC/HEIF is a conditional adapter, not an end-to-end validated decoder in this release. The separate libheif WASM binary could not be downloaded in this build environment. JPEG/Ultra HDR works without it. To try HEIC on an internet-connected browser, expand Phone HDR / HEIC import and permit the pinned CDN codec. Only decoder code is downloaded; images remain local. Alternatively, run vendor/download_heif.py before deployment and host the codec locally. See vendor/README.md for exact dependencies, licensing and tests.

The adapter implements supported SDR, PQ/HLG and a legacy Apple auxiliary-gain convention. ISO Adaptive HDR HEIF tmap, HDR-base/backward maps and unrecognized gain/color conventions are not supported. Test a genuine export from your phone before advertising compatibility. Codec availability and format support are not established by a successful file selection.

5. Educational color-condition previews

The new panel uses the same confirmed source and view direction. It includes cataract-like haze/yellowing, peripheral restriction, central loss, repeatable scattered loss, color-vision deficiency and custom blur/contrast/saturation. Adjust effect amount, angular field/spot diameter, fixation, haze, yellowing and the spot seed. Save a labeled before/after PNG and the settings in the analysis JSON.

The optional checkbox first applies the selected logMAR/Pelli-Robson reduced-detail step, then the educational effect. That color recombination is an adaptation, not a full port of the original DeVAS chromaticity filter. The separate quantitative grayscale panel remains available.

These condition effects are illustrations, not clinical disease-stage models. Black/dim masks label missing image information, not a claim about literal patient appearance. Source measurements and source false color remain unchanged.

6. Existing workflows retained

HDR/EXR inspection, bracket response estimation/reuse, streaming merge without an exposure-count cap, ROI patch calibration, pixel/region measurements, actual cropping, header correction, relative/absolute visibility filtering and numerical exports remain available. Brackets must still be aligned views of a static scene with compatible exposure processing; no alignment, deghosting or camera-RAW decoding was added.

7. First-run check on your host

  1. Open the folder over HTTPS. Load the built-in demo, switch to false color, set linear 0-1000, and save a PNG. Check that the legend is in the saved image.
  2. Use the FOV calculator, confirm/apply geometry, then run a grayscale simulation and one educational color condition. Source measurements should remain unchanged.
  3. Open your HDR or EXR, confirm its supported file scale only when appropriate, and inspect a familiar region before recalibrating it.
  4. Open a phone JPEG and check the explicit HDR/SDR status. For HEIC, enable/install the optional codec and test that route separately.

8. Evidence and limits

Retained numerical suites plus 22 new numerical groups passed. The complete 22-stage sample/regression browser run and 13-stage new-feature browser run passed. Generated Adobe, ISO and Apple-XMP gain fixtures were decoded in Chromium into float32 HDR values. HEIF container, transfer math and RGB16 adapter-contract tests passed, but the actual HEVC codec was unavailable.

Browser tests used production bundles in an in-memory Chromium page with worker/resource-base URL substitutions. They are not tests of your live host, Firefox, Safari or physical mobile devices. No new camera/meter or clinical validation was performed. See TEST_RESULTS.md and METHODS.html for the scope.
