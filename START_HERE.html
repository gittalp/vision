VisionSim HDR Web 0.9.2

Actual evalglare runs inside the browser.

No Python, Node, local Radiance installation, executable path, or external image-processing service is required. The complete website includes the supplied evalglare 3.06 loader and WebAssembly engine. Your photograph is processed locally in browser memory.

Use the new web folder

Upload the complete hdr-analyzer-v092 folder alongside the existing website, retaining its js, vendor, and other subfolders. Open its hosted index.html over HTTP(S), just as with the earlier versions. Do not replace only the main HTML file. The engine is already installed in the package; no manual manifest editing or separate executable upload is needed.

Clearer controls and consistent release labels

The workspace and linked methods pages now display version 0.9.2. The scattered-loss condition is named Diabetic retinopathy simulation; its existing illustrative model is unchanged. DGP interpretation now includes what 0.20 means. No circadian estimator is enabled in this maintenance release.

Parameter help and task regions

Open Source detection and numerical settings for short explanations. The fixed-threshold workflow is unchanged. For a laptop or another task, save a named polygon/circle/rectangle with the existing measurement tool, then choose Saved task region x multiplier. Its source angular mean times the multiplier sets a scalar threshold; the full glare view remains intact.

DGP low-light correction now has one explicit ON/OFF switch. ON is -C l+; OFF is -C l- and is the documented engine default. The initial ON setting is retained so this interface update does not silently change an earlier calculation. Change only the switch to compare correction choices. Reset source-detection settings is separate and does not change this switch, calibration, resolution, sampling or measured lux.

See the source-linked parameter guide for sampling, projection, dim-task restrictions and DGP/UGR/VCP interpretation. Thresholds of 100 cd/m2 or less cannot use this polygon adapter; it stops rather than allowing native -b to be misinterpreted.

Run glare

1. Open, calibrate and confirm geometry. Use the existing crop and image-circle tools, confirm the true projection, and establish absolute luminance. Saved named regions and their steradian results continue to work as before.

2. Prepare the glare copy. Choose the whole-forward-hemisphere route for a complete circular capture and press Prepare / convert glare copy. Equisolid data are actually resampled into angular projection. This changes only a separate glare raster, not the working photograph or calibration. The default 1000 x 1000 analysis size is independent of the source resolution.

3. Press Run evalglare (in browser). The bundled engine is loaded automatically. Inspect DGP, the other returned metrics, source mean luminance and solid angle, and the numbered source-check image. Read the engine warnings and inspect source detection; settings are recorded with the result.

Controls and exports

Skip glare is optional even for a circular image. Cancel stops the separate engine worker. Reset glare only leaves calibration, named regions, and simulations intact. Changes to glare settings, image calibration or geometry require fresh preparation so old results are not silently reused.

Export the result JSON (including the check image), source CSV, diagnostic PNG, raw check HDR, or prepared angular HDR. Field masks and angle rings can be displayed on the result without recalculating its baseline score. The fixed source threshold is adjustable; do not assume a single threshold is appropriate for every scene.

Capture quality and test scope

A full hemisphere needs valid data and correctly confirmed geometry. The limited rectilinear route requires an independent eye-plane illuminance measurement and remains labeled limited-view. No preparation operation recovers missing bright sources or clipped highlights. Low-light/out-of-range engine warnings are displayed instead of being treated as a comfort verdict.

Actual WebAssembly calculations, repeat runs, cancellation, exports, and preservation checks passed in Chromium. Testing used in-memory static-file delivery because navigation is restricted in the test environment. The live host, Firefox/Safari, and the supplied Windows executable were not tested. The current diagnostic source-overlap label refers to a source centroid, not its full footprint.

The original desktop Blackmagic Beta 6.3 is unchanged.
